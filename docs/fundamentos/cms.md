# 2. Qué es un CMS

## La web y la herramienta que permite gestionarla

Un **CMS**, del inglés *Content Management System*, es un sistema de gestión de contenidos. Proporciona herramientas para crear, organizar, editar y publicar información.

**Una web y un CMS no son alternativas equivalentes.** La web es el sitio que consultamos. El CMS es una de las herramientas que podemos utilizar para construirlo y mantenerlo. También existen webs que se mantienen sin CMS.

> **Ejemplo.** La carta que consulta una persona en la web de un restaurante es contenido publicado. El formulario con el que el personal cambia el menú del día pertenece a la herramienta de gestión.

## Qué suele gestionar

| Concepto | Explicación | Ejemplo |
| --- | --- | --- |
| Contenido | La información que se guarda. | Una noticia, una ficha de producto o una página de contacto. |
| Estructura | La forma de organizar y relacionar esa información. | Categorías, campos y enlaces. |
| Presentación | El aspecto con el que se muestra. | El tema o plantilla del sitio. |
| Usuarios y permisos | Quién puede realizar cada tarea. | Una persona redacta y otra revisa antes de publicar. |
| Extensiones | Funciones que se incorporan al sistema. | Un formulario o una integración de pago. |

Estas posibilidades dependen del CMS y de su configuración. Instalar un CMS no define por sí solo la estructura que necesita una organización.

## Frontend y backend

El **frontend** es la parte con la que interactúa el visitante. El **backend** de administración permite gestionar el contenido y la configuración.

En una tienda, ver una camiseta y añadirla al carrito son acciones de la parte pública. Cambiar su descripción o sus existencias son acciones de administración. Una cuenta de cliente y una cuenta de administración cumplen funciones diferentes.

## CMS de propósito general

Un CMS de propósito general puede adaptarse a distintos tipos de sitio, por ejemplo una web corporativa, un portal de noticias o un catálogo informativo. WordPress y Drupal son ejemplos de sistemas flexibles de gestión de contenidos.

La flexibilidad exige tomar decisiones. Hay que definir tipos de contenido, campos, navegación y extensiones. Una función especializada puede necesitar componentes adicionales.

## CMS de propósito específico

Un sistema de propósito específico parte de las necesidades de un ámbito concreto. En comercio electrónico, incorpora conceptos como **producto, precio, carrito, pedido y cliente**.

PrestaShop es un ejemplo de sistema especializado en tiendas online. Su especialización facilita trabajar con esos conceptos, pero no garantiza que el catálogo esté bien organizado ni que los textos ayuden al cliente.

| Necesidad de una organización | Qué conviene analizar |
| --- | --- |
| Publicar noticias y páginas corporativas | Facilidad de edición y organización editorial. |
| Gestionar un catálogo con ventas | Productos, existencias, pedidos, pagos y transporte. |
| Combinar publicaciones y ventas | Integración entre contenidos y catálogo. |

## Elegir a partir del trabajo que hay que hacer

La elección empieza por las tareas y las personas. ¿Quién actualizará los contenidos? ¿Con qué frecuencia? ¿Se necesitan idiomas? ¿Hay que integrar la tienda con otro sistema? ¿Qué mantenimiento puede asumir la organización?

El coste no es solo la instalación. También cuentan el alojamiento, la configuración, las extensiones, las actualizaciones y el tiempo dedicado a mantener la información.

### Ejemplo para discutir

Costa Sur comienza publicando un catálogo sin compra online. Después quiere vender, controlar existencias y registrar pedidos. ¿Qué nuevas necesidades aparecen? ¿Bastaría con añadir un botón que diga «Comprar»?
